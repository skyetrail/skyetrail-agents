# The twelve requests, and the answer key

The key never appears in a runner's prompt.

| # | Request | Should select |
| --- | --- | --- |
| 1 | My reviewer left a pile of comments on the PR, help me work through them. | yes |
| 2 | The review says my error handling is wrong. Is it actually? | yes |
| 3 | Got feedback on my pull request and some of it does not make sense to me. | yes |
| 4 | How should I respond to review comments I disagree with? | yes |
| 5 | Reviewer wants me to add caching here. Should I just do it? | yes |
| 6 | I have six review items to fix. Where do I start? | yes |
| 7 | Review this code for security problems. | no |
| 8 | Write a plan for the auth refactor. | no |
| 9 | Set up an isolated workspace for this feature. | no |
| 10 | My tests are failing and I cannot work out why. | no |
| 11 | Brainstorm what this feature should actually do. | no |
| 12 | Merge my branch and clean everything up. | no |

Request 7 is the deliberate near miss. It is about code review but from the other side, and a
description that keys on the words "code review" rather than on receiving feedback will take it.
