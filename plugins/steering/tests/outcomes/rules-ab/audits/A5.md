## The three fixes to make first

1. **F4. Stop before committing to the person's branch.** Line 86 tells the agent to add the
   worktree directory to `.gitignore` and commit, on the branch that line 44 promised the worktree
   would protect. Report the unignored directory and ask, rather than committing. This is the one
   place the skill does the exact thing it offered to prevent.
2. **F3. Open the project-type lists.** Give a membership test for what a project needs, then
   offer the four commands as examples. Today an unlisted project, such as Maven, .NET, or Ruby,
   gets no setup and no baseline check, and line 158 records that skip as intended behaviour.
   Within the listed set, every `pyproject.toml` gets `poetry install`, which is wrong for a `uv`,
   `pdm`, or `hatch` project.
3. **F6. Forbid weakening the baseline check.** Say that skipping, deleting, or editing a failing
   test to reach the "0 failures" line at 139 is not allowed, and that a failing baseline gets
   reported as it stands. The report template creates the pressure; nothing currently blocks the
   shortcut.

F2 is the next one, and it is also blocking: state what this skill does not cover, name
`finishing-a-development-branch` as the successor at line 37, and say that a direct instruction
from the person wins.
