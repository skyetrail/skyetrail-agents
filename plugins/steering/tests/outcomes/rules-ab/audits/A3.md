## The three fixes to make first

1. **Forbid weakening a check or editing a test to make a suggestion pass.** F8, Blocking defect.
   This skill changes code under reviewer pressure and says nothing about the one shortcut that
   pressure produces. It is the only finding where following the skill as written can leave the
   codebase worse than before the review.
2. **State what the skill does not cover, and name the skill that takes over.** F1, Blocking
   defect, two rules. `requesting-code-review` sits in the same collection and is never named. Add
   the limit and the handoff in one place.
3. **Close the lists, or give each a membership test.** F6, Blocking defect. "When To Push Back"
   at lines 115 to 121 is the costly one: an agent reads a reason that is not on the list as a
   reason not to push back. A trailing "or any other case where the suggestion is wrong for this
   codebase" satisfies the rule. Naming what makes a case a member is stronger.

Next after these, and also Blocking: F4, state the finished outcome in the first lines, so an agent
cannot treat a good reply as the completed work.
