## The three fixes to make first

1. **Close the project-type lists in Steps 2 and 3, and settle the contradiction with the Quick
   Reference.** Lines 106-128 name four ecosystems and stop, so a Maven, .NET, Ruby, or Elixir
   project gets no setup and no baseline, and the finish check the whole skill turns on cannot run.
   Line 157 then tells the agent to skip install for a project line 116 tells it to install. Write
   the membership test first, then give the four as examples, in the form line 53 already uses.

2. **State what the skill does not cover, and name the skill that takes over.** No limit appears
   anywhere in 167 lines, so the Quick Reference reads as the whole set and an agent carries past
   the passing baseline into branch cleanup. Line 37 already dangles a hand-off, "Branch creation
   needed at finish time", with nowhere to send it. `finishing-a-development-branch` is present in
   the collection and resolves.

3. **Assign `$LOCATION` and `$BRANCH_NAME`, and name the "instruction file".** Lines 93-96 run
   `git worktree add` on two variables nothing sets, while the value Step 0 captured sits unused in
   `BRANCH`. An agent runs the command with empty text and creates a worktree at the wrong path.
   Line 153's "instruction file" is named only by nickname and appears as "your instructions" at
   lines 41 and 70.

Next after those: forbid weakening or editing the baseline tests to make them pass (line 130 steers
away from it, but line 138 rewards a clean number and nothing prohibits the shortcut), and say what
happens to the worktree and the `.gitignore` commit when a run stops part way.
