## The three fixes to make first

1. **Define the branch name and the location before the create command.** Step 1b runs `git worktree add "$path" -b "$BRANCH_NAME"` with both variables unset, and Step 0 leaves a same-looking `BRANCH` holding the current branch. State where the new branch name comes from, and set `LOCATION` from the directory the selection step chose. This audit does not apply the fix. Use `writing-skills`.
2. **Stop and ask before committing to the person's branch.** Change "Add to .gitignore, commit the change, then proceed" so the agent reports the unignored directory and waits. As written it breaks the promise Step 0 makes to get consent, which is "It protects your current branch from changes".
3. **Settle one directory-selection order.** Step 1b puts an explicit instruction above an existing directory. The Quick Reference puts the existing directory first. Delete the drifting rows, or restate them to match Step 1b, so an explicit preference wins in both places.

Next after these three: nothing forbids editing a failing baseline test while the report template demands "0 failures", and the four-ecosystem lists in Steps 2 and 3 leave any other project type with no setup and no baseline.
