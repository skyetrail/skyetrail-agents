## Findings

One finding per root cause. A rule that depends on another finding is listed under it.

**F1. No scope limit and no successor. Blocking. Defect.**
The skill never says what it does not cover, and never names the skill that takes over. Dependent
rules: skill-rules Boundary rows 1 and 2, steering Scope out-of-scope row. An agent that reaches
"Ready to implement" at line 140 has no stated limit, so it carries on into implementation, branch
finishing, or worktree removal. `skills/finishing-a-development-branch/SKILL.md` owns the cleanup
and the target never points at it.

**F2. `$LOCATION` and `$BRANCH_NAME` are used and never established. Blocking. Defect.**
Lines 92 to 96. Step 0 assigns `BRANCH`, which is the current branch, not the new one. The skill
never says where the new branch name comes from. An agent that runs the block as written runs
`git worktree add "/" -b ""`, or fails under `set -u`.

**F3. "instruction file" names a file the skill never names. Blocking. Defect.**
Line 153 against lines 41 and 70. Dependent rule: skill-rules Content one-term row. An agent
reading the Quick Reference hunts for a file on disk, such as `CLAUDE.md` or `AGENTS.md`, instead
of reading its own instructions.

**F4. Step 2 and Step 3 hard-code four project types. Blocking. Defect.**
Lines 106 to 119, line 127, line 157. No membership test, no examples marker, and the commands are
ones the model already knows. Dependent rules: skill-rules Content common-knowledge row, steering
Scope stop-and-report row. A Ruby, Java, PHP, .NET, pnpm, bun or uv project gets no setup, and line
157 tells the agent to skip silently rather than report.

**F5. Step 0 reads a non-repository as a normal repo checkout. Blocking. Defect.**
Lines 20 to 24 and line 39. Outside a git repository the two command substitutions fail, `2>/dev/null`
swallows the error, and both variables end up empty. The equality at line 39 then holds, and the
skill proceeds to create a worktree where there is no repository. No stop condition covers this, and
none covers a `git worktree add` failure other than the permission error at line 100.

**F6. Weakening the baseline check is not forbidden. Blocking. Defect.**
Lines 121 to 140. The report template at line 138 demands "0 failures". Line 130 sends a failure to
the user, which helps, but nothing forbids editing or skipping the failing test to reach the
template's wording.

**F7. The report template holes are unmarked. Important. Defect.**
Lines 136 to 140 and lines 36 to 37. A run where the user declined consent at line 45 still emits
"Worktree ready at ", because the template has no variant for working in place. A run that skipped
setup emits "Tests passing (, 0 failures)".

**F8. Partial work on a stop is not stated. Important. Defect.**
Line 86 and line 130. A stopped run can leave a registered worktree and a committed `.gitignore`
change behind. Nothing says whether to remove them, so the next run meets a `.worktrees` directory
it did not create and reads it as existing project state at line 69.

**F9. Things that cannot choose take action verbs. Important. Difference.**
Lines 65, 74, 163, 164, 165. The target works this way throughout and no behaviour changes because
of it. Marked a difference, not a defect.

**F10. The description carries no error text and no casual phrasing. Important. Defect.**
Line 3. A person who types "don't touch my branch", "give me a scratch copy", or who pastes
`fatal: '<branch>' is already checked out` matches nothing in the description. The skill then does
not load, and no isolation is created, which is the outcome the skill exists to prevent.

**F11. Direct instruction precedence is stated only for two decisions. Important. Defect.**
Lines 41 to 45, 65 and 166 give the person precedence over consent and over directory choice. No
general statement exists. Line 164 calls bypassing a native tool "the #1 mistake", so a person who
directly asks for `git worktree add` meets pushback the skill never lets them override.

**W1. The description's trailing clause restates the mechanism. Important. Difference.**
Line 3. It may equally aid discovery. Warn, because the file alone does not settle it.

**W2. The two summary tables restate the body. Important. Difference.**
Lines 142 to 157 and 159 to 167. No behaviour change is nameable. The duplication has already
drifted once, which is F3.

**W3. The announcement at line 14 gives no reason. Important. Difference.**
It constrains how the work is done, and neither correctness nor safety needs it.

**W4. No retry limit is named. Important. Difference.**
Nothing in the skill loops, so no unbounded retry is invited. No limit is stated either.
